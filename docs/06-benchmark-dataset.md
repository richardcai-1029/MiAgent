# 评测数据集说明

| 项目 | MiAgent · 通用 Agent 端侧能力底座 |
|---|---|
| 数据集 | MiAgent-Bench v1.0 |
| 规模 | 10,000 条用例 · 11,349 轮请求 · 27,071 个标准任务 |
| 对应实现 | `bench/suite/`（生成、参考执行、自检），`tests/test_bench_suite.py` |
| 产出 | `bench/data/cases.jsonl`（生成物，不入库）、`bench/data/manifest.json`（统计与校验和） |

---

## 一、用途与边界

数据集服务于四类指标的验证：工具调用准确率、多任务调度成功率、推理速度、资源占用。每条用例同时给出两种标准答案：

- **规划答案**：面对这句话，应拆出哪些任务、调哪个工具、参数填什么、依赖怎么连。用于衡量模型侧的工具调用准确率。
- **执行答案**：照这份计划执行、叠加声明的故障之后，每个调用收到什么参数、得到什么结果、哪些副作用应当发生、目标能否达成。用于衡量框架侧的调度成功率。

数据集只陈述事实，不带阈值：哪个结果算达标不在这里规定。

---

## 二、构造方法

### 2.1 工具目录

评测用 37 个系统工具（`bench/suite/catalog.py`），覆盖日历提醒、位置出行、通讯、内容、订单、媒体、设备七类。与 `miagent/mock_server/tools.py` 的演示工具不同，这里的处理函数**全部是纯函数**：输出只由参数决定，不带内建故障。因此生成数据集时即可算出每个调用的结果，下游引用这个结果的参数也就有了确定的标注值。

每个工具另带两项只供数据集使用的语义：输出能被当作哪一类值引用（号码、地址、店名、文本、时间、订单号、歌曲、城市），以及哪些参数能接收哪一类值的引用。能被引用的输出一律是裸值（一个号码、一个店名），因为框架的数据流传递的是整个结果。

参数类型不全是字符串：音量与亮度是整数，开关是布尔，用来覆盖参数归一化路径。录屏工具的内存开销（300 MB）超过默认配额（256 MB），在默认配额下必然触发 MC-4001。

### 2.2 从任务图到话术

每轮请求先构造任务图，再渲染成一句话：

1. **按结构构造**。单任务、无依赖并行、数据流链、扇入、扇出、菱形、混合七种结构各有构造器；构造完用结构判定函数复核，判定与目标类别不一致就重来。
2. **采样参数**。每个参数有一个标注值与一个说法。多数参数二者相同——规划器的规则是「用户说出的内容原样填入」；工具声明了格式的参数（闹钟的 HH:MM、音量的整数、开关的布尔）说法是口语（「下午一点一刻」「关一下」），标注值是按 schema 换算后的值，另列出评分时也算对的写法。
3. **渲染**。按拓扑序逐个取说法模板；引用处填上游结果的指代（「翻译结果」「那家店」「这个号码」）；相邻两句按依赖关系选连接词（并行用「同时」「另外」，数据流用「然后」「接着」，顺序依赖用「这些都办完之后」）。模板按「哪些参数是引用」分组，同一个工具在参数由用户说出与取自上一步时说法不同。

### 2.3 参考执行

执行答案由 `bench/suite/execute.py` 算出：按依赖先后逐个调用目录里的纯函数，上游失败则下游不执行。它**不依赖 miagent 的调度实现**——评测时拿框架的实际执行去对照它，二者不能出自同一份代码。

故障只描述「这个调用会怎样失败」，不涉及框架怎么应对（重试几次、何时重规划由框架决定，不写进标准答案）：

| 故障 | 含义 | 错误码 |
|---|---|---|
| `transient_first` | 第一次调用超时，再调即成功 | MC-1003 |
| `transient_all` | 每次调用都超时 | MC-1003 |
| `busy` | 资源被占用：餐厅订满、附近无车 | MC-4002 |
| 内存超配额（内在） | 工具内存开销超过握手配额 | MC-4001 |
| 权限未授予（内在） | 用户拒绝了授权，工具不可见 | — |
| 查无结果（内在） | 用户报了不存在的单号，工具置 isError | — |

故障按（工具, 实际参数）匹配，与计划里的任务 id 无关，因此重规划换了 id 的同一个调用仍会遇到同一个故障。

**目标能否达成**：主计划全部完成；或者失败的部分由备选计划接手，且备选计划全部完成。备选计划只在请求里说出了备选方案时存在（「订不上就换鼎泰丰」「叫不到车就直接导航过去」）——用户没说的备选方案，模型没有依据去猜。

## 三、类别与配比

| 类别 | 条数 | 含义 |
|---|---:|---|
| `single` | 1,400 | 单个工具调用 |
| `parallel` | 1,400 | 2~4 个互不依赖的调用，可同层并行 |
| `chain` | 1,800 | 2~4 步数据流链：上一步的结果是下一步的参数 |
| `fan_in` | 900 | 一个任务同时引用两个以上上游的结果 |
| `fan_out` | 700 | 一个结果分给两到三个下游 |
| `diamond` | 700 | A →（B ‖ C）→ D，D 取 B 或 C 的结果并在另一个之后执行，或在两者都完成后执行 |
| `mixed` | 1,100 | 上述有依赖的结构外加 1~3 个独立任务，最多 7 个任务 |
| `multi_turn` | 1,000 | 2~3 轮对话：后一轮用上一轮查到的值（「给刚才查到的号码发短信」），或切换话题 |
| `no_tool` | 450 | 闲聊、常识与算术，标准答案为空计划 |
| `unsupported` | 250 | 句中有目录里没有的能力（订机票、转账），能做的部分照做，整体不可达成 |
| `permission_denied` | 300 | 用户拒绝了某项授权，依赖它的任务及其下游做不成 |

有依赖的五类结构（链、扇入、扇出、菱形、混合）合计 5,200 条，占 52%。

### 3.1 叠加项

在七种结构类别上按比例叠加两类情形，以标签记录：

**故障**（35%，共 2,759 条）：`transient_first` 818、`transient_all` 820、内存配额降低 876、`busy` 可恢复 74 / 不可恢复 77、查无结果 94。内存类故障模拟端侧内存紧张时握手下发更低配额：配额取目标工具开销减 1 MB，开销不低于它的工具都会触发 MC-4001。

**模型非理想输出的模拟**（30%，共 2,404 条）。只供标注答案驱动的评测使用，**不改变标准答案**：

| 标签 | 模拟的偏差 | 对应的框架防线 |
|---|---|---|
| `noise:fence` / `prose` / `trailing_comma` | 规划输出带代码块围栏、前后客套话、尾随逗号 | JSON 截取（`extract_json`） |
| `noise:invalid_once` | 第一次输出不合 schema | 自修复重试 |
| `noise:stringified_ref_once` | 第一次把 `$from` 引用写成字符串 | schema 阶段拒绝并自修复 |
| `sim:arg_drift` | 规划把某个参数写偏 | 结果校验判未通过并给出修正 |
| `sim:omit_step` | 规划漏掉末端的一步 | 完成校验指出缺口，重规划补做 |

`arg_drift` 只挑无副作用的调用：写偏的调用会被真实执行，副作用无法由校验撤回。后两项只加在没有故障的轮次上。

### 3.2 分布

| 难度等级 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| 条数 | 2,113 | 2,934 | 2,833 | 1,502 | 618 |

| 首轮任务数 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 条数 | 667 | 2,580 | 1,374 | 2,611 | 1,906 | 370 | 357 | 135 |

| 首轮依赖层数 | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| 条数 | 667 | 4,111 | 2,769 | 1,940 | 513 |

难度等级的规则：分数 =（任务数 − 1）+（层数 − 1），各轮累加；多一轮加 2，叠加故障加 2，叠加模拟偏差加 1；等级 = 1 + min(4, 分数 ÷ 2 取整)。

其他：标准任务中含数据流引用 10,864 处；37 个工具全部被用到（最少的 `play_music` 只能从搜歌结果引用，出现 61 次）；11,349 轮中 8,820 轮可达成；1,649 轮带「不应发生的调用」；原话长度中位数 38 字、P95 94 字、最长 167 字。

用例还带会话标识、优先级（前台约 70%）与握手配额（并发上限 1/2/3/4，以 2 为主），供多请求并发的评测使用。

## 四、记录格式

一行一条用例（JSON）。以一条扇入用例为例（`permissions` 与 `expected.calls` 有删节）：

```json
{
  "id": "mb-08467", "category": "fan_in", "level": 3,
  "tags": ["noise:invalid_once", "sim:arg_drift"],
  "shape": {"tasks": 3, "depth": 2, "width": 2, "data_edges": 2, "order_edges": 0,
            "max_fan_in": 2, "max_fan_out": 1},
  "session": "conv-08467", "priority": "foreground",
  "permissions": ["alarm.write", "booking.write", "..."],
  "budget": {"max_memory_mb": 256, "max_concurrent_calls": 2,
             "max_call_timeout_ms": 5000, "power_saving": false},
  "turns": [{
    "request": "推荐一家附近的咖啡馆，顺便在下周五找个空闲时间，然后在那个空档订那家店",
    "gold": {"tasks": [
      {"id": "t1", "description": "推荐一家附近的咖啡馆", "required_tool": "system.recommend_place",
       "arguments": {"category": "咖啡馆"}, "dependencies": []},
      {"id": "t2", "description": "在下周五找个空闲时间", "required_tool": "system.find_free_slot",
       "arguments": {"date": "下周五"}, "dependencies": []},
      {"id": "t3", "description": "在那个空档订那家店", "required_tool": "system.book_restaurant",
       "arguments": {"name": {"$from": "t1"}, "when": {"$from": "t2"}},
       "dependencies": ["t1", "t2"]}]},
    "fallback": null,
    "accept": {},
    "faults": [],
    "expected": {
      "achievable": true,
      "calls": [{"id": "t3", "tool": "system.book_restaurant",
                 "arguments": {"name": "Manner Coffee(清河店)", "when": "下周五 14:00"},
                 "result": "已预订 Manner Coffee(清河店)，下周五 14:00",
                 "status": "done", "error": null, "flaky": false}, "..."],
      "effects": [{"tool": "system.book_restaurant",
                   "arguments": {"name": "Manner Coffee(清河店)", "when": "下周五 14:00"}}]},
    "forbidden": [],
    "simulate": {"planner_noise": "invalid_once",
                 "arg_drift": {"task": "t2", "param": "date", "value": "后天"}}
  }]
}
```

| 字段 | 说明 |
|---|---|
| `gold.tasks` | 首次规划的标准任务图，字段与框架的 `TaskSpec` 一致，可直接喂给计划 schema 校验 |
| `fallback.tasks` | 接手失败部分的标准任务图；`replaces` 指明接替主计划里的哪个任务 |
| `accept` | 口语换算类参数的其他可接受写法 |
| `faults` | 注入的故障，按（工具, 实际参数）匹配 |
| `expected.calls` | 参考执行的逐个调用：实际参数、结果、状态（done / failed / blocked）、错误 |
| `expected.effects` | 应发生、且只应发生一次的副作用调用 |
| `expected.achievable` | 用户目标能否达成 |
| `forbidden` | 不应发生的调用；`arguments` 为 null 表示该工具任何参数都不应调用。多轮里是上一轮已做过的调用，权限类用例里是不可见的工具 |
| `simulate` | 模拟的模型偏差，见 3.1 |

## 五、质量保证

`python -m bench.suite.check` 对每一条用例重新确认标注成立，任一不成立即报错并指出用例：

- 标准任务图通过**框架自己的**计划 schema（工具名收进可见工具的枚举）与任务图结构校验
- 参考执行里每个实际发出的调用，参数已是工具 schema 的规范形态（归一化不改变它）
- 每个字符串参数的标注值出现在这一轮的原话里，或是前几轮执行的结果；口语换算类参数除外
- 引用只指向同一份计划里更早的任务；备选计划接替的任务确实存在
- 每条故障都对应参考执行里的某个调用（声明了的故障一定会被触发）
- 重做参考执行，结果与文件记录一致
- 结构判定与类别一致；首轮原话在全数据集中不重复
- 订餐厅引用的推荐结果是能订座的类别

生成是确定的：同一 seed 与条数永远得到逐字节相同的文件，`manifest.json` 记录 seed 与 SHA-256。

```bash
.venv/bin/python -m bench.suite.generate          # 生成，默认 10000 条、seed 20260928
.venv/bin/python -m bench.suite.check             # 自检
```

## 六、已知局限

- **话术由模板生成**。127 个说法模板、35 个结果指代与词表组合出不重复的首轮原话，句式多样性低于真实用户，也没有错别字、口误与方言。模型侧准确率在这份数据上的结果，不等同于在真实用户话术上的结果。
- **单一工具目录**。37 个工具与规划器一次性全部可见，没有覆盖工具数上百、需要先检索工具的场景。
- **结果是合成的**。工具返回的是确定的假数据；端侧真实系统服务的时延与失败分布没有体现，故障按声明注入。
- **多轮只覆盖承接与话题切换**。没有指代消解更复杂的情形（「把刚才第二个改一下」）、没有对上一轮的纠正与撤销。
- **可恢复故障偏少**。备选方案只在用户说出时存在，因此带备选计划的轮次只有 74 轮；其余故障的正确结局是如实报告做不成。
